# 买不买｜冲动消费投票裁判所

**课程项目立项与原型说明**

## 一、项目概述

「买不买」是一款面向大学生和初入职场年轻人的匿名消费决策应用。用户在付款前提交一份消费申请，写下商品、价格、心动理由、顾虑与备选方案。其他用户投出「批准买」或「禁止剁手」，并可以解释自己为什么这么投。申请人稍后填写真实购买结果，应用据此更新个人消费记录。用户也能加入攒钱小组，和有类似目标的人一起打卡。

项目把干预提前到付款前，再用购买后的复盘检验决定。投票提供参考，购买决定由申请人作出。

## 二、目标用户与需求

| 典型场景 | 用户遇到的问题 | 产品回应 |
| --- | --- | --- |
| 晚上看到限时促销，想立刻下单 | 价格和倒计时占据注意力，预算、用途与替代方案容易被忽略 | 用简短的申请表整理信息，让其他人根据约束给出意见。 |
| 想听一个客观意见，犹豫要不要问熟人 | 熟人可能顾及关系，申请人也可能不愿让熟人知道自己的预算 | 用匿名身份参与，并通过申请内容设置讨论焦点。 |
| 买完或忍住之后，记不清上次为什么这样选 | 单笔金额无法解释选择过程，纯记录很难帮助下次判断 | 将申请、投票、评论和真实结果保留为同一笔档案。 |
| 想坚持一个月少买盲盒或闲置衣服 | 一个人很容易忘记目标，也缺少可见的进展 | 在攒钱小组立目标，每天记录一次完成情况。 |

首轮验证面向同校学生。设计假设是大家在有明确消费场景时愿意发表简短意见，且申请人在看到意见后有动力回来复盘。用访谈和原型任务检验这两个假设，再决定校园推广的节奏。

## 三、原型页面与操作路径

| 页面 | 主要信息与操作 |
| --- | --- |
| 裁判大厅 | 按数码科技、穿搭美妆、兴趣爱好、日常生活等类别筛选，可按推荐、最新发布、投票最多排序。支持快速投票和进入申请详情。 |
| 发起消费申请 | 填写商品、金额、预算、心动理由、顾虑和替代方案，可附商品图。表单校验后发布。 |
| 申请详情 | 查看消费约束、投票分布和匿名评论。作者可以记录实际决定，遇到不当内容可从详情举报。 |
| 趣味榜单 | 浏览最有争议、驳回最多和热评最多三个榜，点选条目回到详情。 |
| 攒钱自律小组 | 通过「发现小组」加入公开目标，在「我的小组」记录每日打卡，也可创建私密小组。 |
| 我的档案 | 查看自己的申请和复盘状态、已有账单及消费统计，也可以手动记录实际支出。 |

**决策路线**　裁判大厅 → 发起消费申请 → 申请详情 → 投票与评论 → 作者复盘 → 我的档案与账本。

**自律路线**　攒钱小组 → 加入小组或创建目标 → 今日打卡 → 查看自己的累计进展。

## 四、业务规则与统计口径

1. **发布。** 商品名、分类、金额与购买理由经校验后生成一笔申请。金额以人民币计价，预算、顾虑、替代方案和附图可选。
2. **裁判。** 复盘前，旁观者可以投票，同一匿名身份对同一申请最多保留一张有效票。改投时移除原选项上的这一票，再计入新选项。评论和投票独立，作者可以在评论里补充情况。
3. **复盘。** 只有作者可以记录「已买」或「忍住没买」。复盘后保留票数和评论，停止接收新的投票与评论。已买记录生成对应账单，重复操作沿用同一条。作者改为忍住后，关联账单随之移除。手动记账记录独立保存。
4. **统计。** 忍住比例以「忍住没买笔数 ÷ 已复盘笔数」计算。省下金额按忍住没买的申请金额累计。实际支出由已买申请的关联账单与手动账单合计。假设三笔申请分别为已买 ¥300、忍住 ¥200、待复盘 ¥100，再手动记录支出 ¥35，忍住比例为 50%，省下 ¥200，实际支出为 ¥335。
5. **小组。** 公开小组可浏览和加入，成员每天可为同一小组打卡一次。原型中的私密小组仅创建者可见。
6. **加急。** 大厅的推荐排序优先显示待裁决的加急申请，其余按发布时间排列。加急采用模拟流程，社区投票仍使用统一的计票规则。
7. **周榜。** 每周一零点开启新一轮，按发布时间纳入本周申请。「最有争议」将两边票数配对，每对计两分。「驳回最多」按制止票数排列，「热评最多」按评论条数排列。

## 五、界面与交互设计

暖白底和珊瑚红建立轻松的裁判主题。页面使用中文无衬线字体，标题、说明、金额、计票信息形成独立层级。投票选项同时显示文字、图标和票数，颜色用于加强区分。商品图辅助识别，预算、用途和顾虑与价格并列出现，保证申请的讨论焦点可见。

宽屏在裁判大厅同时呈现申请列表与社区信息，窄屏按主要操作顺序排成单列。表单分组放置商品、预算与购买理由，详情内把投票、评论与作者复盘置于各自的操作区。按钮反馈、筛选切换和票数变化采用短时过渡，减少动态效果设置下仍提供文字和选中态反馈。

## 六、技术方案与数据模型

前端使用 Uni-app 与 Vue 3，共用 H5 和微信小程序的页面与业务逻辑。课程演示默认加载示例申请与小组，操作通过设备本地存储保存，便于重复演示。共享体验由可选的 uniCloud 服务提供。接入后，服务端基于匿名会话区分申请作者、投票人和账本所有者，并校验发布、计票、复盘和打卡等关键操作。微信小程序的预览和发布需要在对应微信项目下完成。

| 数据 | 主要内容和关系 |
| --- | --- |
| 匿名会话 | 内部身份与会话凭据，用于确认操作归属。公开页面展示匿名昵称。 |
| 消费申请 | 作者、商品、类别、价格、预算、购买理由、顾虑、替代方案、图片、加急标记和复盘状态。 |
| 投票与评论 | 分别关联申请与参与身份。投票区分买和劝退，评论记录内容与发布时间。 |
| 攒钱小组与打卡 | 记录小组目标、可见范围、成员和打卡日期。用小组、成员与日期确定每日打卡。 |
| 账单 | 记录所有者、项目名、金额、日期及可选的申请关联。复盘关联账单与手动账单可追溯。 |
| 举报 | 记录举报对象、原因和处理所需时间信息，为校园内测审核提供入口。 |

## 七、运营、内容治理与商业设想

初期在同校范围招募体验者，用「开学装备怎么选」「大促囤货值不值」等主题形成一批真实、可讨论的申请。榜单强调意见和消费场景，适合在校园群或朋友圈传播。关注新用户是否看懂规则、申请能否收到第一条有效反馈，以及用户是否愿意回来完成复盘。

内容治理从匿名昵称、基础敏感词过滤与举报入手。校园内测安排人工复核，优先处理公开个人信息、针对申请人的辱骂和低俗内容。发帖时建议裁去截图中的订单号、收货地址及账户信息。公开页展示申请和讨论所需的信息。账本与私密小组依照访问权限展示。

基础发布、投票和评论按长期免费设计。可验证的增值方向包括小额加急曝光、会员统计报告和私密小组权益。加急权益仅提高曝光顺序，实际收到的票数由社区参与决定。后续若引入平价商品或理财科普合作，合作内容需有明确标识。以上收入模式以付费意愿、内容质量和审核成本为评估依据，当前仅提供免费的加急演示。

## 八、项目计划与验收

| 阶段 | 交付与验收 |
| --- | --- |
| 本周立项与原型 | 完成立项说明、页面导航与交互原型。能够按提交、参与、复盘、自律四类任务演示。 |
| 期末开发与联调 | 在 H5 和微信开发者工具中核验主流程与布局。若开通 uniCloud 服务空间，用独立会话验证多人共享、权限和数据更新。 |
| 校园内测 | 小范围邀请同学完成任务，并观察发布完成率、首条反馈耗时与复盘率。按反馈调整字段、说明和榜单规则。 |

内测记录使用统一口径。发布完成率按成功发布次数除以参加发帖任务的总次数计算。首条反馈耗时从发布时刻算到第一张票或第一条评论。复盘率按观察期内已记录实际结果的申请占比计算，并记录尚未收到反馈的申请数量，便于定位流程的停留环节。

### 答辩演示顺序

1. 从大厅查看一个示例申请，切换投票选项，观察票数和选中态，再发送一条建议。
2. 发布一笔「¥299 的降噪耳机」申请，补充预算、顾虑和替代方案，上传一张商品图。确认详情和大厅均能找到对应记录。
3. 选择「最终下单」，在个人账本确认出现一笔 ¥299 记录。再切换为「成功忍住」，核对该关联账单及统计变化。
4. 添加一笔手动支出，加入一个公开小组并完成当天打卡，再打开本周榜单并从条目回到申请详情。
5. 重新打开应用，确认本机的操作留存。若切换到已开通的共享环境，用两个独立匿名会话核验双方能看到同一条公开申请、评论和票数，并确认只有作者可复盘。
